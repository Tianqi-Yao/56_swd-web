# 设计：节点端采集与上传 + Firebase 结构与权限（第一期第 1 项）

日期：2026-10-12。需求来源：`docs/SPEC.md` v0.2，下文简称 SPEC。本文覆盖 SPEC 第 6 节第一期的第 1 项，并扩展到 Pi 上的正式采集脚本（用户 2026-10-12 决定本轮一起做）。种子数据和网站另写设计。

标注说明：没有标注的是用户确认过的内容；标 **（我的判断）** 的是我定的，用户可以推翻。

## 1. 要解决什么，为什么

田间每个陷阱节点是一台 Raspberry Pi。正式部署时，它每 30 分钟拍一张粘虫卡，在本地算出 male SWD 的数量，只把计数和每天一张中午缩略图传到 Firebase。网站的全部功能（时间序列、健康热力图、告警）都依赖这里存下的数据。

现在 Pi 上还没有这条正式流程。`data/Rpi_contain_YOLO/run_code/run.py` 是采集训练数据用的，每次用多个焦距拍十几张，不跑模型。`run_code/yolo/yolo_ncnn.py` 是对一张固定图片做切块推理的演示脚本。Firebase 那边也还没有数据结构和权限规则。

节点走 4G，经常断网，还会遇到时钟出错、传感器读不到等情况。无论遇到哪种，数据都不能丢。

采集和上传是两个解耦的程序（SPEC 第 3 节）：
- **采集脚本**：拍照，推理，把结果写成 `outbox/` 里的 JSON 文件。
- **上传程序**：负责把 JSON 送到 Firebase。

它们之间只通过 `outbox/` 文件夹交换数据。

## 2. 目标

- `edge/` 文件夹（SPEC 里叫 `edge-uploader/`，改名是因为现在还包含采集脚本），内容包括：
  - `capture.py`
  - `uploader.py`
  - 共用的 `config.example.ini`
  - 两套 systemd service 和 timer
  - README

  安装只要三步：复制到 Pi、填好配置、启用两个 timer。
- 白天每 30 分钟产生一条计数记录。每条记录最终都写进 RTDB。中午那张缩略图能传到 Storage。每台节点都有心跳。
- 断网时数据不丢，恢复后自动补传。重复上传不会产生重复数据。
- 原图留在 Pi 上，按存储上限滚动删除，删除之前让技术员看得到。
- `database.rules.json` 和 `storage.rules` 达到演示级权限：每台 Pi 只能写自己的数据，网站用户登录后才能读。
- 采集脚本以外的部分都能在本地 Firebase Emulator 和 Mac 上测试，不依赖云端项目，也不依赖相机。

## 3. 不做什么

- 不处理 ESP32 和 Pi 之间的数据传输。SPEC 第 9 节第 1 条假设温湿度和电压日志已经在 Pi 上可读。
- 不计算日统计、告警和时钟故障判定，这些由后续的 Vercel Cron 做。本轮只把判定要用的服务器时间存下来。
- 不发邮件或短信（属于第二期告警）。本轮只把滚动删除的状态上报到心跳，见 5.4。
- 不做种子数据，不做网站页面。
- 不做严格的安全策略。CLAUDE.md 的要求是先能演示，严格的后补。
- 不改模型，不重新训练。

**做成这样就算失败，哪怕代码能跑：**
- 断网、Firebase 报错或遇到坏文件时丢了数据，或者一个坏文件把整个队列卡住。
- 上传程序需要装 Firebase SDK 之类的额外依赖，或者需要常驻进程。
- 传感器读不到时编一个数值出来，而不是填 null。
- 读数按上传时间建索引。必须按采集时间建索引（SPEC 第 1 节）。
- 原图悄悄被删掉，技术员事先完全不知道。

## 4. 约束

- **上传程序**只能用 Python 3 标准库加 `requests`（SPEC 第 3 节）。
- **采集脚本**可以用 Pi 上已经装好的 `ultralytics` 和 `opencv`（`yolo_ncnn.py` 已经在用），但不再新增依赖。拍照调用系统自带的 `rpicam-still`。
- Firebase 通过 REST API 访问：Auth、RTDB 和 Storage 都走 HTTPS。
- 设备时钟是美国中部时间，用户假设它一直准确。`acquired_at` 是带时区偏移的 ISO8601 字符串。
- 开发环境：conda `swd-web`（Python 3.12 + Node 22）。Pi 上的 Python 版本未知，代码要兼容 Python 3.9+。**（我的判断）**
- 现有 Pi 的用户名是 `paalab`，代码放在 `~/Desktop/run_code/`。新的 `edge/` 不依赖这个路径，所有路径都写在配置里。
- `data/` 不进 git。测试用的样例另外手写一份，放到 `edge/tests/fixtures/`。

## 5. 已经定下的部分

### 5.1 总体决定

- 本轮范围：第一期第 1 项，加上 Pi 上的正式采集脚本。
- 新建一个 Firebase 项目，不复用旧的 smart-trap-website 项目。开发阶段先用 Emulator。云端项目由用户在控制台创建。
- trapId 直接用设备名（如 `MSU1`）。一个 Pi 就是一个陷阱，RTDB 路径里的 `{trapId}` 就是 `device_id`。
- 传感器字段由上传程序补全，采集脚本只写计数相关的字段。
- 采集脚本和上传程序放在同一个文件夹，共用一份 `config.ini`。

### 5.2 采集脚本 `capture.py`

- **运行方式。**单次运行：拍一张，算完，写好 JSON 就退出。由 systemd timer 在 06:00–20:00 之间的每个整点和半点启动（`OnCalendar=*-*-* 06..19:00,30:00` 加上 `20:00`）。
- **拍照。**用 `rpicam-still`，做法同 `cam_test/capture_one.py`，不用 Picamera2，避免全分辨率时内存不够。
  - 分辨率（`--mode`）写在配置里，64MP 节点和 16MP 节点各填各的。
  - **对焦用固定镜头位置**（`--lens-position`）。每台节点装好后，用 `cam_test/calibration.py` 标定一次，把结果写进配置。不在每次拍照时自动对焦。
- **推理。**把 `yolo_ncnn.py` 的切块推理改写成一个函数：输入图片路径，返回检测框列表 `[[x1,y1,x2,y2,conf], ...]`（原图像素坐标）。
  - 参数不变：切块 640，重叠 20%，置信度 0.25，切块间做 NMS（阈值 0.45），切块不够 640 的边缘补黑边。
  - 去掉画框、保存切块图和 tqdm 进度条。
  - 模型路径和 `model_version` 写在配置里。
- **计数。**`count_male_swd` = NMS 之后的检测框个数。模型只有一个类别 `swd`，按 SPEC 视为 male SWD。
- **缩略图。**当天第一次在 12:00–12:29 之间拍成功的那张就是中午图。处理方法：
  - 用 opencv 把原图缩到长边 1280 像素，存成 JPEG。如果超过 500 KB，就逐步降低质量，直到不超过。
  - 这条记录额外带上 `thumb`（缩略图文件名）、`boxes`，以及原图尺寸 `img_w`、`img_h`，供网站按比例画框。
  - **（我的判断）**"当天是否已经有中午图"，用缩略图目录里有没有当天的文件来判断。
- **写 outbox。**先写 `outbox/{device_id}_{YYYYMMDD_HHMMSS}.json.tmp`，写完后改名成 `.json`。`acquired_at` 用拍照那一刻的设备本地时间。`infer_ms` 是推理耗时。
- **失败处理。**拍照失败、图片读不出或推理报错时，这一次不写记录，只写日志后退出。网站会把这个时段显示为缺失；心跳仍由上传程序照常写。

### 5.3 上传程序 `uploader.py`

- **运行方式。**单次运行。systemd timer 每 5 分钟启动一次，把 `outbox/` 扫一遍就退出，不常驻。
- **扫描顺序。**按文件名排序处理 `outbox/*.json`。修改时间在 60 秒以内的文件这一轮先跳过 **（我的判断）**。每条记录依次处理：
  1. 校验
  2. 补全传感器字段
  3. 有缩略图就先传缩略图
  4. 写读数
- **出错时怎么办：**
  - **网络错误或 5xx**：立即结束这一轮。当前文件和后面的文件都留在 `outbox/`，下次重试。
  - **401/403**：同样整轮停下，文件都不动 **（我的判断）**。RTDB 的 REST 接口对"没权限"和"Rules 校验没过"返回的是同一种错误，分不出来。如果当成坏文件处理，一次配置错误就会把积压的文件全挪走。
  - **本地就能判断的问题**（JSON 解析失败、缺必填字段、`device_id` 和配置不一致）：文件移到 `bad/`，写日志，接着处理下一条。
  - **缩略图传不上**（文件不存在、超过 500 KB，或 Storage 返回 4xx）：读数照常写入，只是没有缩略图，同时写日志 **（我的判断）**。
  - **成功**：文件移到 `sent/YYYY-MM-DD/`。
- **幂等。**读数用 PUT 写到固定路径，重复上传只会覆盖，不会出现两份。
- **心跳。**每轮结束时 PATCH `heartbeat/{id}`，即使 `outbox/` 是空的也写，这样网站能分清"节点活着、只是没拍照"和"节点掉线"。心跳写失败不影响读数。
- **清理。**`sent/` 里超过 30 天的文件删除，天数可以配置。
- **传感器补全**（只补缺失或为 null 的字段）：
  - `temp_c`、`rh`：读 `logs/YYYY-MM-DD.csv`（无表头，`date,time,temp,rh`），取采集时间前后 5 分钟内最近的一条。16MP 节点的日志和 ESP32 用同一种格式，以后所有节点统一。
  - `battery_v`：同时读 `logs/voltage.csv` 和 `logs/voltage_YYYY-MM.csv`（无表头，`date,time,V,percent`；固件 6 月中起改成按月存），取前后 15 分钟内最近的一条。16MP 节点没有电压文件，填 null。
  - **电压一律原样上传，不做过滤。**`12.60/99` 和 `0.x V` 都是真实测量：太阳能板大，电池平时一直是满的；连续阴雨时电池会真的耗光（2024、2025 年用铅酸电池，2026 年换成磷酸铁锂后好了）。
  - 日志里的时间不带时区，是设备当地时间，而且是准的；采集季都在中部夏令时内。所以直接拿它和 `acquired_at` 去掉偏移后的本地时间比较，不做时区换算。
  - 时间解析不了的行（如 `72:41:18`）、`NaN` 和空值直接跳过。
  - `free_gb` 用 `shutil.disk_usage` 读当前值。
- **null 字段在 RTDB 里不存在**，因为 RTDB 写入 null 等于删除这个键。网站把"字段不存在"当作"缺失"显示。

### 5.4 原图存储与滚动删除

- 原图留在 Pi 上，不上传。原图目录最多占整个磁盘总容量的 60%。
- 每次拍照前检查：超过 60% 就从最旧的原图开始删，直到降回 60% 以下。
- 技术员要能事先知道，好在需要数据时尽快去现场拷贝。本轮的做法 **（我的判断）**：
  - 上传程序在心跳里多写三项：
    - `imgUsedPct`：原图目录占磁盘的百分比
    - `oldestImageAt`：现存最旧一张原图的时间
    - `imgRolling`：是否已经开始滚动删除
  - 第一期的节点健康页面显示这三项，按"距离开始删除还有多远"或"已经在删"来提示。
  - 邮件和短信通知放到第二期的告警里做。
  - 提醒阈值 **（我的判断）**：超过 50% 时显示"即将开始滚动删除"，到 60% 时显示"正在滚动删除，最早保留到 X"。
- 实现时要注意：如果卡比较小（比如 32 GB），原图占 60% 后，剩余空间可能低于 SPEC 里 `free_gb < 15` 的告警线，造成长期误报。这条告警阈值要在网站阶段按卡的容量重新考虑。本轮只记录这个风险，不改。

### 5.5 Firebase 结构与权限

- 路径沿用 SPEC 第 4 节。本轮只会写入三条路径：`readings`、`thumbs`、`heartbeat`。
- **设备身份。**每台 Pi 用一个 Email/Password 账号。管理员在 `/devices/{uid}` 写入设备名（如 `"MSU1"`），Rules 查这张表判断这个账号能写哪台设备的数据。不用 custom claims，因为那需要 Admin SDK。
- **设备的写权限。**只能写 `readings/$id`、`thumbs/$id`、`heartbeat/$id`，条件是 `root.child('devices').child(auth.uid).val() === $id`。写读数时校验 `count_male_swd` 是非负整数。
- **网站用户。**`/users/{uid}` 存在，就视为已登录用户，可以读全部数据。`users` 和 `devices` 只有 `role == "admin"` 的用户能写。角色字段本轮只存，不按它区分页面权限。
- **服务器时间。**每条读数和每次心跳都带 `serverTime: {".sv": "timestamp"}`，供以后判定时钟故障（SPEC 第 5 节）。
- **Storage。**缩略图路径是 `thumbs/{device_id}/{YYYY-MM-DD}.jpg`。Storage Rules 读不到 RTDB，所以演示期只要求三条：已登录、`image/jpeg`、小于 500 KB。严格版后补，并在 README 里注明。
- 14 个设备账号以后用脚本批量创建。部署到云端项目和创建账号之前，都先问用户。

## 6. 数据格式

### 6.1 outbox JSON（采集脚本写，上传程序读）

文件名是 `{device_id}_{YYYYMMDD_HHMMSS}.json`，按文件名排序就是按时间排序。

| 字段 | 必填 | 说明 |
|---|---|---|
| `device_id` | 是 | 必须和配置里的一致 |
| `acquired_at` | 是 | 带时区偏移的 ISO8601，设备本地时间 |
| `count_male_swd` | 是 | 非负整数 |
| `model_version`、`infer_ms` | 否 | 原样上传 |
| `boxes`、`img_w`、`img_h` | 否 | 只有中午那条有。`boxes` 为 `[[x1,y1,x2,y2,conf], ...]`，原图像素坐标 |
| `thumb` | 否 | 只有中午那条有，是缩略图目录里的文件名 |
| `temp_c`、`rh`、`battery_v`、`free_gb` | 否 | 采集脚本不写，由上传程序补全 |

### 6.2 写入 RTDB 的数据

- `readings/{id}/{YYYY-MM-DD}/{HHMMSS}`：上表中除 `thumb`、`boxes`、`img_w`、`img_h` 以外的全部字段，再加上 `serverTime`。日期和时分秒直接取自 `acquired_at` 的本地时间部分，不做时区换算。
- `thumbs/{id}/{YYYY-MM-DD}`：`{storagePath, acquiredAt, boxes, imgW, imgH}`。
- `heartbeat/{id}`：`{deviceTime, serverTime, lastReadingAt, imgUsedPct, oldestImageAt, imgRolling}`。
  - `deviceTime` 是 Pi 的当前时间。
  - `lastReadingAt` 是本轮最后一条上传成功的读数的 `acquired_at`。本轮一条都没上传成功时，这一项不更新。

## 7. 配置（`config.ini`）

至少包括以下几类：
- **设备和账号：**`device_id`，账号邮箱和密码，Web API key，RTDB URL，Storage bucket。可选 `emulator_host`，填了就改连 Emulator。
- **目录：**`outbox`、`sent`、`bad`、`thumbs`、`state`、原图目录、传感器日志目录。
- **相机：**`rpicam-still` 的 `mode`、`lens_position`。
- **模型：**模型路径、`model_version`。
- **存储：**原图占用上限（默认 60%）、`sent` 的保留天数。

仓库里只放 `config.example.ini`。

## 9. 怎么算完成

**上传程序**的单元测试全部通过，至少覆盖下列情况：
- 正常上传。
- 缩略图传不上时，计数照常上传。
- 遇到 401/403 时整轮停下，文件不动。
- 60 秒内新写的文件被跳过。
- 断网时文件保留，恢复后按顺序重试。
- 坏文件移进 `bad/`，不阻塞后面的队列。
- 传感器补全，包括 `voltage.csv` 和按月的电压文件。
- 时间窗口外的记录、NaN、坏时间、RTC 故障日期都能正确处理。
- token 刷新。
- 心跳里的原图存储状态正确。

**采集脚本**的单元测试全部通过：
- 切块推理函数在样例图上返回的框数，与原 `yolo_ncnn.py` 对同一张图的结果一致。
- 中午图的判定、缩略图小于 500 KB、outbox 文件的原子写入。
- 滚动删除只删最旧的原图，删到 60% 以下就停。
- 拍照失败时不写记录。
- 拍照部分用一个替身代替 `rpicam-still`。

**Rules** 在 Emulator 上的测试全部通过：
- 设备不能写其他设备的数据。
- 未登录不能读。
- 普通用户不能写 `users`。

**Emulator 端到端测试：**
- 放 3 条样例记录（其中 1 条带缩略图），运行一次上传程序，确认 `readings`、`thumbs`、`heartbeat` 和 Storage 里的文件都在。
- 停掉 Emulator 再运行，文件留在 `outbox/`。
- 恢复 Emulator 后，补传成功。

**真机验证**（需要用户配合，不阻塞本轮其他工作）：在一台 Pi 上跑通"拍照 → outbox → Emulator 或云端"。

**README** 写清楚在 Pi 上从零装好的步骤，包括对焦标定。
