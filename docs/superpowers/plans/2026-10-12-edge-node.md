# 节点端采集与上传 + Firebase 规则 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Pi 上每 30 分钟拍照、切块推理、写 outbox JSON；另一个程序把 JSON 和中午缩略图可靠地上传到 Firebase；配套 RTDB/Storage 演示级 Rules。

**Architecture:** `edge/` 是一个扁平的 Python 文件夹，整份复制到 Pi。`capture.py` 和 `uploader.py` 是两个单次运行的入口，由各自的 systemd timer 拉起，只通过 `outbox/` 交换数据。Firebase 一律走 REST。Rules 放在仓库根目录，用 Firebase Emulator 和 Vitest 测试。

**Tech Stack:**
- Pi 端：Python 3.9+；`requests`；Pi 上已有的 `ultralytics` 和 `opencv`；`rpicam-still`；systemd
- 开发和测试：pytest、`responses`；Node 22、firebase-tools、`@firebase/rules-unit-testing`、Vitest

**Spec:** `docs/superpowers/specs/2026-10-12-edge-node-design.md`

## Global Constraints

- `uploader.py` 及其依赖模块只能 import 标准库和 `requests`；`capture.py` 及其依赖模块可以额外用 `cv2`、`numpy`、`ultralytics`。`uploader.py` 的导入链里不能出现 `cv2`。
- 兼容 Python 3.9+：每个模块开头写 `from __future__ import annotations`，不用 `match`，不用 3.10+ 的 API。
- Firebase 只用 REST，不装 Firebase SDK。
- 所有路径都从 `config.ini` 读，不写死 `/home/paalab`。
- 写读数和建索引都用 `acquired_at` 的本地日期和时间（去掉时区偏移），不做时区换算，也不用上传时间。
- 传感器读不到就填 `None`（JSON 里是 `null`），不能编数值；电压原样上传，不做过滤。
- 日志用 `logging` 输出到 stdout。
- 测试数据和样例不能引用 `data/` 下的文件；只有推理一致性测试例外，样例图不存在时跳过。
- Firebase 项目 id 在仓库里先用 `demo-swd-web`（Emulator 专用）。

## Review Focus

1. **RTC 故障时间**（`acquired_at` 是 `2000-01-01T...`）：照常上传到 `readings/MSU1/2000-01-01/...`，既不拒收也不改写。网站会据此判定时钟故障。（Task 4 测试）
2. **传感器日志目录或当天的文件不存在**：对应字段填 `None`，程序不崩溃，照常上传。（Task 2 测试）
3. **`acquired_at` 不带时区偏移，或者根本不是时间**：文件移到 `bad/`，不阻塞队列。（Task 4 测试）
4. **断网几天后补传几十个文件，中途 token 过期**：按文件名顺序全部传完，过期时自动刷新 token。（Task 3、Task 4 测试）
5. **写 outbox 时磁盘满或写入异常**：不能留下半个 `.json` 文件，只允许残留 `.tmp`，而上传程序不扫 `.tmp`。（Task 1 测试）

### Task 3: Firebase REST 客户端

**Files:**
- Create: `edge/fbclient.py`
- Test: `edge/tests/test_fbclient.py`

**Interfaces:**
- Consumes：`Config`（Task 1）
- Produces：
  - 三种错误类型：
    - `NetworkError(Exception)`：连接失败、超时，或服务器返回 5xx。
    - `AuthError(Exception)`：返回 401 或 403。
    - `ClientError(Exception)`：其他 4xx，带 `.status: int`。
  - `class FirebaseClient`：
    - `__init__(self, cfg: Config, session: requests.Session | None = None, clock: Callable[[], float] = time.time)`
    - `put(self, path: str, data: dict) -> None`
    - `patch(self, path: str, data: dict) -> None`
    - `upload_jpeg(self, storage_path: str, data: bytes) -> None`
  - 每次请求前，如果 token 不存在，或者离过期不到 5 分钟，先登录或刷新。token 缓存在 `cfg.state_dir/token.json`，内容为 `{id_token, refresh_token, expires_at}`。
- 端点（默认是云端，`emulator_host` 有值时改用括号里的地址）：
  - 登录：`POST https://identitytoolkit.googleapis.com/v1/accounts:signInWithPassword?key={api_key}`，body 为 `{email, password, returnSecureToken: true}`。（Emulator：`http://{host}:9099/identitytoolkit.googleapis.com/v1/...`）
  - 刷新：`POST https://securetoken.googleapis.com/v1/token?key={api_key}`，form 为 `grant_type=refresh_token&refresh_token=...`。（Emulator：`http://{host}:9099/securetoken.googleapis.com/v1/token`）
  - RTDB：`{db_url}/{path}.json?auth={id_token}`。（Emulator：`http://{host}:9000/{path}.json?ns=demo-swd-web&auth=...`）
  - Storage：`POST https://firebasestorage.googleapis.com/v0/b/{bucket}/o?name={quote(storage_path, safe='')}`，header 带 `Authorization: Firebase {id_token}` 和 `Content-Type: image/jpeg`。（Emulator：`http://{host}:9199/v0/b/...`）
  - 所有请求的 timeout 都是 30 秒。

### Task 4: 原图存储状态与上传程序 `run_once`

**Files:**
- Create: `edge/images.py`（本任务只写 `image_status`，`prune_images` 在 Task 6）、`edge/uploader.py`
- Test: `edge/tests/test_uploader.py`

**Interfaces:**
- Consumes：
  - `Config`、`parse_acquired_at`、`local_naive`（Task 1）
  - `read_temp_rh`、`read_battery`、`free_gb`（Task 2）
  - `FirebaseClient` 和三种错误类型（Task 3）
- Produces：
  - `image_status(images_dir: Path, disk_path: Path, state_dir: Path, now: datetime) -> dict`，返回 `{"imgUsedPct": float, "oldestImageAt": str | None, "imgRolling": bool}`。
    - `imgUsedPct` = `images_dir` 下所有文件的总大小 ÷ 磁盘总容量 × 100，保留 1 位小数。
    - `oldestImageAt` 由最旧的文件名 `YYYYMMDD_HHMMSS.jpg` 转成 `"YYYY-MM-DDTHH:MM:SS"`。
    - `imgRolling` 的判断：`state_dir/last_prune.txt` 存在，且里面记的时间距离 `now` 不到 24 小时。
  - `run_once(cfg: Config, client: FirebaseClient, now: datetime) -> dict`，返回 `{"sent": int, "bad": int, "skipped": int, "stopped": str | None}`。`stopped` 的取值为 `None`、`"network"` 或 `"auth"`。
  - `main(argv: list[str] | None = None) -> int`：读 `--config` 参数（默认是脚本同目录的 `config.ini`），调用 `run_once`，返回 0。

处理逻辑（按设计文档 5.3）：
1. 扫描 outbox：
   - 按文件名排序扫 `outbox/*.json`。
   - `mtime` 距离 `now` 不到 60 秒的文件跳过，计入 `skipped`。
2. 校验，任一项不通过就把文件移到 `bad/`，计入 `bad`：
   - JSON 解析失败
   - 缺少 `device_id`、`acquired_at`、`count_male_swd` 中的任何一个
   - `device_id` 与配置不一致
   - `count_male_swd` 不是非负整数
   - `parse_acquired_at` 抛错
3. 补全传感器字段。字段缺失或为 `None` 时才补：`temp_c`、`rh`、`battery_v`、`free_gb`。
4. 如果记录里有 `thumb`：
   - 读 `thumbs_dir/thumb`。
   - 上传到 `thumbs/{id}/{YYYY-MM-DD}.jpg`。
   - 然后 PUT `thumbs/{id}/{date}` = `{storagePath, acquiredAt, boxes, imgW, imgH}`。
   - 出错时：文件不存在、超过 500 KB 或 `ClientError`，只写一条 warning，继续往下；`NetworkError` 和 `AuthError` 向外抛。
5. 写读数：PUT `readings/{id}/{YYYY-MM-DD}/{HHMMSS}`。
   - 内容为记录本身去掉 `thumb`、`boxes`、`img_w`、`img_h`，再加上 `serverTime: {".sv": "timestamp"}`。
   - 值为 `None` 的字段不写。
6. 成功后，把文件移到 `sent/YYYY-MM-DD/`，日期用上传那天的本地日期。
7. 出错时：
   - `NetworkError`：设 `stopped="network"`，停止扫描。
   - `AuthError`：设 `stopped="auth"`，停止扫描。
   - `ClientError`：文件移到 `bad/`。
8. 循环结束后（包括提前停止的情况）写心跳：PATCH `heartbeat/{id}`，内容为：
   - `deviceTime`：`now.isoformat(timespec="seconds")`
   - `serverTime`
   - `lastReadingAt`：只有本轮至少成功上传一条时才写
   - `image_status` 返回的三个字段

   写心跳时的任何错误都只写日志，不影响结果。
9. 最后删除 `sent/` 下超过 `sent_keep_days` 天的日期子目录。

### Task 6: 采集脚本 `capture.py` 与原图滚动删除

**Files:**

- Create: `edge/capture.py`

**Interfaces:**
- Consumes：
  - `Config`、`write_json_atomic`（Task 1）
  - `load_model`、`detect`（Task 5）
- Produces：
  - `prune_images(images_dir: Path, disk_path: Path, max_pct: float, state_dir: Path, now: datetime) -> list[Path]`
    - 按文件名从旧到新删除，直到 `images_dir` 的总大小 ≤ 磁盘总容量 × `max_pct` / 100。
    - 只要删了文件，就把 `now.isoformat()` 写进 `state_dir/last_prune.txt`。
    - 磁盘总容量通过 `shutil.disk_usage` 获取；测试里 monkeypatch 这个函数。
  - `take_photo(cfg: Config, out_path: Path, run=subprocess.run) -> bool`
    - 运行 `rpicam-still -n --immediate --mode {camera_mode} --lens-position {lens_position:.2f} -o {out_path}`。
    - 返回码为 0 且文件存在、非空，才算成功。
    - 超时 120 秒；超时也返回 False。
    - `camera_mode` 在配置里填 `9248:6944:12:P` 这样的完整写法。
  - `is_noon_slot(now: datetime, thumbs_dir: Path) -> bool`：`now` 的本地时间在 12:00:00–12:29:59 之间，并且 `thumbs_dir` 里还没有 `{YYYYMMDD}_*.jpg`。
  - `make_thumbnail(img, out_path: Path, long_side: int = 1280, max_bytes: int = 500_000) -> None`
    - 用 `cv2.resize` 缩小，插值方式为 `INTER_AREA`。
    - JPEG 质量从 85 开始，每次降 10，直到文件不超过 `max_bytes`，最低降到 35。
  - `capture_once(cfg: Config, now: datetime, model, run=subprocess.run) -> Path | None`：返回写入的 outbox 文件路径，失败时返回 None。
  - `main(argv: list[str] | None = None) -> int`：成功返回 0，失败返回 1。

`capture_once` 的流程：
1. `prune_images`
2. 拍照，存为 `images_dir/{YYYYMMDD_HHMMSS}.jpg`，失败就返回 None。
3. `cv2.imread`，读不出就返回 None。
4. `detect`，同时用 `time.monotonic` 计时，得到 `infer_ms`。推理抛异常也返回 None。
5. 生成记录：
   - `device_id`
   - `acquired_at`：`now.isoformat(timespec="seconds")`，`now` 带本地时区。
   - `count_male_swd`：`len(boxes)`
   - `model_version`、`infer_ms`
6. 如果 `is_noon_slot` 为真：
   - 生成 `thumbs_dir/{YYYYMMDD_HHMMSS}.jpg`。
   - 记录里加上 `thumb`（文件名）、`boxes`（坐标保留 1 位小数，conf 保留 3 位）、`img_w`、`img_h`。
7. 调用 `write_json_atomic(outbox_dir/f"{device_id}_{YYYYMMDD_HHMMSS}.json", record)`。
